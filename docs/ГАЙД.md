# RemnaSetup (proqopev) — полный гайд по деплою нод

Практическая инструкция: как быстро поднимать ноды на новой схеме (Cloudflare wildcard,
маскировка, WARP-egress, фаервол) **без** упирания в лимиты Let's Encrypt.

---

## 0. Что нового (коротко)

| Фича | Зачем |
|---|---|
| Caddy → Cloudflare **wildcard** DNS-01 | имена нод не светятся в CT-логах |
| **Готовый серт без ACME** (`import-cert`) | много нод на один серт, не жжём лимит LE |
| Случайные **сайты-маскировки** + настоящий 404 | нода выглядит обычным сайтом |
| **WARP-egress** для xray (авто) | IP ноды не виден как выход |
| **ufw + fail2ban** | базовая защита, порты управления только для панели |
| **Выбор версии ноды** (`NODE_VERSION`) | совместимость панель↔нода |

---

## 1. Разовая подготовка (один раз на всю сеть)

### 1.1. Домен на Cloudflare
1. Cloudflare → *Add a Site* → домен → тариф **Free**.
2. У регистратора сменить **NS** на выданные Cloudflare. Проверка: `dig NS твойдомен` → NS Cloudflare.
3. API-токен: *My Profile → API Tokens → Create Custom Token* →
   **Permissions:** `Zone → DNS → Edit`, **Zone Resources:** `Include → Specific zone → твойдомен`.

### 1.2. Выпустить wildcard-серт ОДИН раз («cert master»)
На **одной** ноде с рабочим доступом к Cloudflare (без IPv6-багов) ставим Caddy в ACME-режиме:
```bash
DOMAIN=master.твойдомен CF_API_TOKEN='токен' MONITOR_PORT=8443 \
bash <(curl -fsSL https://raw.githubusercontent.com/proqopev/RemnaSetup/refs/heads/main/install.sh) install-caddy-node
```
Дождись в логах `certificate obtained successfully` (`journalctl -u caddy -f`).

### 1.3. Забрать файлы серта
На «cert master» серт лежит тут:
```
/var/lib/caddy/.local/share/caddy/certificates/acme-v02.api.letsencrypt.org-directory/wildcard_.твойдомен/
```
Скопируй **два файла** себе на комп (через WinSCP):
- `wildcard_.твойдомен.crt`
- `wildcard_.твойдомен.key`

> ⚠️ Лимит Let's Encrypt: **5 сертов на `*.твойдомен` за 7 дней**. Поэтому выпускаем ОДИН раз
> и дальше только **раскидываем файлы** — на каждой ноде ACME больше не трогаем.

## 2. Установка НОВОЙ ноды (быстро, без ACME)

### 2.1. DNS
В Cloudflare добавь A-запись: **случайное имя** (напр. `x7f2qk9z`) → IP ноды, **Proxy status: DNS only (серая тучка).**
> Оранжевая тучка ломает Reality — обязательно серая.

### 2.2. Проверь, что IP «чистый» (до установки!)
Прогони IP на достижимость из РФ — check-host.net → **TCP connect** на `IP:443` из точек Москва/СПб.
Если РФ-точки красные → IP уже в бане, **не бери его**, проси другой/меняй хостера.

### 2.3. Залей серт на ноду (WinSCP)
Скинь два файла в `/root/`:
- `/root/wildcard.crt`
- `/root/wildcard.key`
(имена ровно такие — скрипт их ждёт по умолчанию).

### 2.4. Установка одной командой
```bash
NON_INTERACTIVE=true \
DOMAIN=x7f2qk9z.твойдомен \
WILDCARD_CRT=/root/wildcard.crt WILDCARD_KEY=/root/wildcard.key \
MONITOR_PORT=8443 NODE_PORT=3001 SECRET_KEY='ключ_из_панели' \
NODE_VERSION=3.2.2 \
WEBSERVER=caddy INSTALL_WARP=y BBR_ANSWER=y \
PANEL_IP=IP_ПАНЕЛИ \
bash <(curl -fsSL https://raw.githubusercontent.com/proqopev/RemnaSetup/refs/heads/main/install.sh) install-node
```
При заданных `WILDCARD_CRT/KEY` Caddy берёт **готовый серт** (без ACME, без токена, лимит не тратится),
ставит WARP + маршрутизацию, фаервол, ноду.
> `NODE_VERSION` подгони под свою панель (у панели 2.7.x — ставь **3.2.2**, не `latest`).

### 2.5. Настрой профиль в Remnawave (вручную)
В xray-конфиге ноды:

**Reality-инбаунд:**
- `target` → `127.0.0.1:8443`
- `serverNames` → `["x7f2qk9z.твойдомен"]` (реальное имя ноды, не wildcard)
- `xver` → `0`

**WARP-egress:**
```json
"dns": { "servers": ["https://1.1.1.1/dns-query"], "queryStrategy": "UseIPv4" }
```
```json
{ "tag": "warp", "protocol": "freedom",
  "settings": { "domainStrategy": "ForceIPv4" },
  "streamSettings": { "sockopt": { "mark": 1 } } }
```
```json
"routing": { "rules": [
  { "type":"field", "ip":["geoip:private"], "outboundTag":"BLOCK" },
  { "type":"field", "domain":["geosite:private"], "outboundTag":"BLOCK" },
  { "type":"field", "protocol":["bittorrent"], "outboundTag":"BLOCK" },
  { "type":"field", "network":"tcp,udp", "outboundTag":"warp" }
] }
```

### 2.6. Обнови подписки
После смены домена клиентам нужен новый SNI — **переимпортируй подписку** (или дождись авто-обновления).

### 2.7. Проверка
```bash
# на ноде: серт на месте
echo | openssl s_client -connect 127.0.0.1:8443 -servername x7f2qk9z.твойдомен 2>/dev/null | openssl x509 -noout -subject -issuer
# на ноде: WARP жив
wg show warp | grep -iE "handshake|transfer"
```
С клиента: `https://www.cloudflare.com/cdn-cgi/trace` → `warp=on` и IP Cloudflare (не IP ноды).

## 3. Перевод СТАРОЙ (уже рабочей) ноды на новую схему

1. Cloudflare: A-запись нового случайного имени → IP ноды (DNS only).
2. WinSCP: залей `wildcard.crt` + `wildcard.key` в `/root/`.
3. Импорт серта (Caddy без ACME):
   ```bash
   bash <(curl -fsSL https://raw.githubusercontent.com/proqopev/RemnaSetup/refs/heads/main/install.sh) import-cert
   ```
4. WARP-egress (если ещё не настроен на этой ноде):
   ```bash
   bash <(curl -fsSL https://raw.githubusercontent.com/proqopev/RemnaSetup/refs/heads/main/install.sh) setup-warp-routing
   ```
5. В панели: обнови `serverNames` (новое имя), проверь `target: 127.0.0.1:8443`, добавь WARP-outbound (п.2.5).
6. Переимпортируй подписки.

## 4. Шпаргалка по командам

Запуск: `bash <(curl -fsSL https://raw.githubusercontent.com/proqopev/RemnaSetup/refs/heads/main/install.sh) <команда>`

| Команда | Что делает |
|---|---|
| *(без команды)* | интерактивное меню |
| `install-node` | полная установка ноды |
| `install-caddy-node` | только Caddy |
| `import-cert` | перевести Caddy на готовый серт (без ACME) |
| `setup-warp-routing` | WARP-egress на уже стоящей ноде |
| `install-warp` | только WARP |
| `update-node` | обновить Remnanode |

Ключевые env: `DOMAIN`, `MONITOR_PORT`, `NODE_PORT`, `SECRET_KEY`, `NODE_VERSION`,
`WILDCARD_CRT`/`WILDCARD_KEY`, `CF_API_TOKEN`, `PANEL_IP`, `INSTALL_WARP`, `BBR_ANSWER`,
`SKIP_FIREWALL`, `SKIP_FAIL2BAN`, `NON_INTERACTIVE`.

## 5. Грабли и тонкости (важно!)

- **Rate-limit LE (5/неделю на `*.домен`)** — не выпускай серт на каждой ноде. Выпусти один раз,
  дальше `import-cert`. Не гоняй полную переустановку «ради серта» — каждый заход жёг слот.
- **A-запись только DNS only (серая тучка)** — иначе Reality не работает.
- **`target` = `127.0.0.1:8443`**, не голое `"8443"`.
- **Версия панель↔нода** — нода `3.3.x` не работает с панелью `2.7.x` (меняли handshake).
  Пинь `NODE_VERSION=3.2.2`. Апгрейд: сначала панель, потом ноды.
- **WARP = точка отказа** — при «всё через warp», если туннель лёг, у ноды пропадает интернет
  (клиенты подключаются, но страницы не грузятся). Спасает watchdog; следи `wg show warp`.
  Не вешай WARP-профиль на ноду, где host-часть WARP не настроена (`setup-warp-routing`).
- **WARP IPv4-only** — держи в конфиге `dns.queryStrategy: UseIPv4` и `ForceIPv4`, иначе IPv6-утечка.
- **Хостер режет UDP 2408** — если `wg show warp` без handshake: смени `Endpoint` в `/etc/wireguard/warp.conf`
  на `162.159.192.1:2408` (или `:500`, `:4500`) и `systemctl restart wg-quick@warp`.
- **PostUp только в `[Interface]`** warp.conf (выше `[Peer]`), иначе wg-quick падает.
- **Проверяй IP на чистоту ДО деплоя** (check-host, TCP на :443 из РФ). Забаненный вход-IP лечится
  только заменой — конфиг не поможет.
- **Пинг ≠ VPN** — РКН режет по протоколу/порту/SNI, а ICMP проходит. Не ориентируйся на пинг.

## 6. Ротация при бане IP

Забанили вход-IP (клиенты не коннектятся, из дома даже SSH не идёт) — **меняй адрес**:
1. Новый IP (лучше другой хостер/ASN — банят подсетями), проверь чистоту (п.2.2).
2. Новая случайная A-запись → новый IP (DNS only). Wildcard-серт переиспользуется — в CT-логах ничего нового.
3. `import-cert` + `setup-warp-routing` на новой ноде, WARP-профиль в панели.
4. Обнови `serverNames` и адрес ноды в панели, раздай подписки. Старую — в утиль.

Наша обвязка (decoy, wildcard, WARP) **снижает частоту** банов, но уже заблокированный IP —
только на замену. Ротация — норма; хардненинг нужен, чтобы новые ноды жили дольше.
